# Phase 3 — The Financial Supplement F1–F8, Assessed

**Prepared by `P3-TST-003` (2026-09-17), for the exit review to check rather than assemble.**

This is the first phase the `PHASE_GATES.md` §3 financial supplement binds — Phases 0–2 recorded
it *not applicable* and said so. This document assesses each criterion against named tests as
they stand today; **the ruling belongs to `P3-DOC-001`**, which re-assesses with recounted
numbers at the gate. Every `Class#method` named here is also named by a `MUTATION_TESTING.md`
§2 row, so `MutationDemonstrationTest` holds these references to the code on every build —
a renamed test fails the build rather than leaving this table pointing at nothing.

## The register, and the one row that cannot exist yet

`MUTATION_TESTING.md` §2 now carries a row for every invariant the **catalogue** marks
`Phase: 3` — nineteen, of which the plan's §6 table lists seventeen (`INV-REC-05` and
`INV-AUD-04` sit outside it; the plan's own closing paragraph rules that the catalogue is the
set, so this is the predicted drift recorded rather than a contradiction) — **except
`INV-AUD-04`**, whose mechanism Phase 3 deliberately did not build: no threshold, no
second-approver flow, four-eyes recorded as ADR-0010's debt by `P3-TSK-017`. A row would be a
false claim. The build will fail naming it the moment Phase 3 flips `COMPLETE`, which is known
in advance this time; **`P3-TSK-021`** owns the mechanism and its row, before `P3-DOC-001`.
This is the supplement's one open item, and it is a criterion-3 concern rather than an F-row:
no F criterion is failed by it, and the gate must not be passed around it.
